rev学习笔记5-PE/ELF文件格式

也是一个现在不知道为什么要学的知识。但是绝大多数情况下这是rev的基础知识之一，说不定什么时候就能用上了呢。
先从最简单的ELF/PE文件开始。

ELF文件格式

ELF全称为Executable and Linkable Format，大多数情况下可以视作Linux上的可执行文件，类似于Windows上的exe文件。
ELF文件分为很多种：relocatable、executable和shared object。
relocatable文件也称为目标文件，通常后缀是.o/.ko，这个目前在rev题里没见过；
shared object文件也称为共享库，大概对标windows的dll文件，后缀通常为.so.x(如libc.so.2)，是在运行时导入的外部数据；
executable文件也就是最常见的可执行文件，对标Windows的exe文件。

–ELF文件头

那么如何确认一个文件是ELF文件呢？
可以直接使用file命令。

还可以查看文件头，这里用十六进制编辑器（010）或者hexdump之类的命令都可以。

number of program headers：总共有多少个program header；

–ELF的节（Sections）和段（Segments）
节是ELF文件中代码和数据的最小组织单位。
在程序编译的“链接”这一步时，来自不同 .o 文件的节合并并且打包成段；
在程序执行时，程序会把具有相同内存权限的节合并成一个段来加载。
这也就代表着，一个段可能包含多个节，只要它们在内存里的权限是相同的。

–ELF的节头（Section Headers）
关于ELF文件中所有节的信息都储存在节头（Section Header）里面。

以下是Section Header Table里面常见也常用的一些节的名称：
——
.text：可执行代码。
.rodata：只读数据（如字符串常量）。
.data：已初始化的全局/静态变量。
.bss：未初始化的全局/静态变量（在文件中不占空间，加载时分配零页内存）。
.symtab：符号表（函数和变量的名称和地址）。
.strtab：字符串表，存储符号名称等字符串。
.dynamic：动态链接信息。
.plt 与 .got：动态链接的过程链接表和全局偏移表。
.shstrtab：节区名称字符串表。
——

输出的信息中包括：

Name：节的名称

Addr：节在文件中的地址。
Off：相对上一个节的地址偏移量
Flg/Flag：权限
——

通过节表我们就可以看到具体的节在程序中的相对地址了。

–ELF的程序头（Program Headers）
只有Executable和Shared object文件有文件头表。
程序头的作用在于：指导操作系统如何将文件加载到内存，它主要描述各个段（Segments）的信息。
可以通过

来查看程序头。

一些常见的段类型：
——
LOAD：需要被加载到内存的段。一个程序通常至少有一个可执行的 LOAD 段（代码）和一个可写的 LOAD 段（数据）。从权限视角，分为只读段（包含 .text 和 .rodata节）和可读写段（包含 .data 和 .bss 节）。
DYNAMIC：包含动态链接信息。
INTERP：指定动态链接器的路径。
——

输出的信息中包括：
——
Offset：段在文件中的危战
VirtAddr：段在内存中的起始地址
PhysAddr：段的实际地址
Size：段在文件中的大小；
MemSize：段在内存中的大小；
Flag：权限。
——

PE文件格式
PE文件，全称Portable Executable File Format。
常见的PE文件格式有dll、exe、ocx、sys等。

–一些基本概念
虚拟内存地址（Virtual Address，VA）是指令被装入内存后的地址。
文件偏移地址（File Offset Address，FOA）是数据在PE文件中的地址，也就是相对于文件开头地址的偏移。
装载基址（Image Base）是PE文件载入内存时的基址。默认是0x400000（EXE），0x10000000（DLL），但是也可以自定义。
相对虚拟内存地址（Reverse Virtual Address，RVA）=VA-Image Base。
